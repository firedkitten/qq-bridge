# qq-bridge 云端部署：配置推荐与云厂商对比

> 目标：把这套「QQ ↔ SnowLuma ↔ 桥接 ↔ DSH」搬到云上，7×24 在线，本机可以关机。
> 本文基于本机实测（2026-10-24 采样）与公开报价整理；报价会变，**下单前以控制台结算页为准**。

---

## 0. 结论先行

| 项 | 结论 |
|---|---|
| 操作系统 | **Windows Server 2022 数据中心版（带桌面体验）**，唯一可行路线（见 §1） |
| CPU / 内存 | **2 核 4G 可行、够用（推荐）；2 核 2G 不行**。内存总需求约 2.7–3.7 GB，其中 Windows 桌面体验自己就吃 1.3–1.6 GB（见 §2.2） |
| 系统盘 | **60G 起步，80G 舒服**（Windows 装完 15–20G + QQNT 2G + 项目 0.6G + 页面文件/日志） |
| 带宽 / 流量 | **3–5 Mbps + 200–500 GB/月 流量包**，纯文字对话根本跑不满 |
| 地域 | **中国内地**（广州 / 上海 / 北京优先）。香港/海外 IP 登录 QQ 更容易被风控要求验证、乃至反复踢下线 |
| 预算 | 含 Windows 授权的大厂 **约 100–150 元/月**；小厂 Windows VPS **约 44–60 元/月** |
| 买法 | **先按月买最便宜的一台验证 QQ 能不能稳定登录（1–3 天），稳了再换大厂买 1–3 年** |
| 不需要 | 备案（不开 80/443、不绑域名）、GPU（模型在 DeepSeek 云端）、CDN、数据库 |

## 1. 为什么必须是 Windows（这条决定了全部成本）

SnowLuma 不是「跑在服务器上的程序」，它是**挂进 QQ 客户端进程的原生模块**：

- `<SnowLuma 安装目录>\native\` 下是 `snowluma-win32-x64.dll`（414 KB）+ `snowluma-win32-x64.node`（344 KB），平台名写死在文件名里；
- `src/bridge.js:2954` 的注释写明：「SnowLuma 用原生组件（`native/snowluma-win32-x64.{dll,node}`）挂进 QQ 客户端进程」；
- 发行包名也是 `SnowLuma-v1.14.20-**win-x64**-lite.zip`。

所以云主机必须能装 **Windows 版 QQNT 客户端**并且有图形会话（扫码登录、加载原生 DLL）。这带来三个直接后果：

1. 必须有 Windows 授权 → 单价抬高 20–30%（阿里云轻量的公开说法就是 Windows 比 Linux 贵这个幅度）；
2. 必须有 RDP 或 VNC 能进桌面 → 会话保持、开机自启要做对（见 §6）；
3. **不能选「仅 Linux 活动机型」**——很多厂商的秒杀价、学生价、首单价明确只给 Linux。

> 如果你愿意改网关，能省钱：换 NapCat（Linux/Docker 原生）后 2核2G 的 Linux 机就能跑，年费能压到 200–400 元。代价是 `src/snowluma-conn.js`（214 行）要重写，且 `bridge.js` 里绑死 SnowLuma 语义的部分（reserved2 模式、转发消息、表情收藏、拍一拍、wake 配置、10 秒 token 自愈）都要重新适配，工作量以周计。**现阶段不建议动**，见 §5 方案 C。

## 2. 配置怎么算出来的

### 2.1 实测体积

| 对象 | 文件数 | 体积 |
|---|---|---|
| `<仓库路径>`（含 `node_modules`） | 4,746 | 30.5 MB |
| `<SnowLuma 安装目录>\...\win-x64` | 89 | 151.9 MB（`node.exe` 93.9 MB、`index.mjs` 9.4 MB） |
| `<用户目录>\.dsh` | 18,269 | 343.0 MB |
| 合计 | — | **约 525 MB** |
| 再加 Windows 版 QQNT | — | 约 1 GB 级 |

磁盘完全不是瓶颈，40G 也能装下；真正的瓶颈是**内存**和**续费价格**。

### 2.2 内存预算（7×24 常驻）

> ⚠️ 关键陷阱：**任务管理器里 QQ 看起来只占 90 MB，那是「工作集」，不是它真正要的内存。**
> 本机实测（QQ 挂在托盘、没有开聊天窗口）：
>
> | 指标 | 5 个 QQ 进程合计 |
> |---|---|
> | 工作集 WS（任务管理器「内存」列） | **93.5 MB** |
> | 私有提交 PM（真正的内存需求） | **800.6 MB** |
>
> 差了 8.5 倍。99% 的网页/教程都说「QQ 才占 100 MB」，就是这么来的。

| 组件 | 常驻内存（按「实际需要」算） |
|---|---|
| Windows Server 2022 桌面体验（空闲，含可回收缓存） | **1.3 – 1.6 GB** |
| QQNT（5 个进程，私有提交） | **0.8 GB** |
| SnowLuma（自带 `node.exe`，`index.mjs` 9.4 MB 打包进内存 + 原生 hook） | 0.3 – 0.6 GB |
| qq-bridge（`:3100`） | 0.1 – 0.2 GB |
| DSH Web（`:3080`，含会话历史） | 0.2 – 0.5 GB |
| **合计** | **约 2.7 – 3.7 GB** |

→ **结论：2C4G 可行，2C2G 不可行。**
- **4 GB**：装完约剩 0.3–1.3 GB 余量，正常跑没问题；建议关掉 Defender 实时防护 / SysMain / Windows Search / DiagTrack（见 §2.4），把余量留在 1 GB 以上。
- **2 GB**：Windows 桌面体验单选就占 1.3–1.6 GB，剩 400–700 MB 要装下一个私有提交就 0.8 GB 的 QQNT——**必然靠页面文件硬撑**，表现为 RDP 卡、消息延迟、偶发进程被杀。这不是调优能救的。
- 轻量应用服务器**普遍不支持降配**（腾讯云明确不支持），但**支持升配**。所以稳妥打法是先买 4G，真不够再原地升 8G。

### 2.3 为什么网上都说「2C2G 就够」

因为那些教程**几乎全是 Linux + NapCat / LLOneBot 的无头方案**，和这套 Windows 方案不是一个量级：

| | Linux + NapCat（常见教程） | 本方案 Windows + SnowLuma |
|---|---|---|
| 操作系统 | Ubuntu/Debian，无图形界面，空闲 **150–250 MB** | Windows Server 2022 **桌面体验**，空闲 **1.3–1.6 GB** |
| QQ | **无头协议实现**，不装官方客户端，进程 200–400 MB | **必须装官方 QQNT 客户端**，私有提交 800 MB |
| 登录方式 | 命令行走扫码接口 / 密码 | 必须有桌面扫码，DLL 注入 QQNT 进程 |
| 同等并发下的总内存 | **0.8 – 1.5 GB** → 2C2G 绰绰有余 | **2.7 – 3.7 GB** → 至少 4 GB |

差的不是「你项目写得重」，而是**平台底座差了一个完整操作系统 GUI + 一个 Electron 级客户端**，这两项加起来就 2 GB 出头。所以「别人 2C2G 能跑」是真的，但套到这个方案上不成立。

### 2.4 如果只买 4G，这些优化必做

```powershell
# 关实时防护（机器人只连 127.0.0.1，风险可控；也可只把项目目录加入排除）
Set-MpPreference -DisableRealtimeMonitoring $true

# 关 SysMain（预读，对 SSD 无收益，纯占内存）
Stop-Service SysMain; Set-Service SysMain -StartupType Disabled
# 关 Windows Search 索引
Stop-Service WSearch; Set-Service WSearch -StartupType Disabled
# 关诊断追踪
Stop-Service DiagTrack; Set-Service DiagTrack -StartupType Disabled
```

- 视觉效果 → 性能选项 → 只保留「平滑屏幕字体边缘」；
- 页面文件设**固定 4 GB**（不要交给系统自动管理，避免动态扩展时卡顿）；
- 用「性能监视器」看两个计数器：`Available MBytes` 长期 > 300 MB、`Pages/sec` 不要长期 > 20，超了就是真不够；
- QQNT 保持托盘、不开聊天窗口，内存会低不少（上面 93 MB 工作集就是这个状态）。

### 2.5 CPU 与网络

- **CPU：2 核足够。** 推理在 DeepSeek 云端，本地只做消息编排、Markdown→纯文本、图片解码；轻量实例是 100% CPU 性能（非突发型），2 核扛得住。
- **带宽：3 Mbps 足够。** QQ 文本消息量极小，`maxSendPerMinute 8 / PerHour 60` 的节流下，正常用量估计 **5–20 GB/月**。200 GB 流量包绰绰有余，只有语音/大量图片才会往上走（`voice.enabled` 现在是 `false`）。
- **不需要固定公网 IP 的高价套餐**，也不需要独立带宽，轻量的共享带宽包足够。

### 3.2 三个必须知道的坑

1. **促销价基本都是 Linux-only 或「产品首单」**。腾讯云轻量 2C4G「一年 200 多」是 Linux 首单价，Windows 要另外加钱；第二年续费恢复原价、没有回归首单折扣（有用户明确吐槽「第二年直接翻倍」）。
2. **Windows 授权费是主要差价来源**。大厂轻量的「Windows 实例套餐」比同配 Linux 贵 20–30%，且**不与 Linux 秒杀价叠加**。若你手里有 Windows Server 授权，可以走 BYOL，但个人用户基本拿不到便宜的批量许可。
3. **轻量实例的硬限制**：不支持指定 CPU 型号、不支持 IPv6、**不支持降配**、只有公网**出方向**流量计费（入方向免费）、流量超额按 0.8 元/GB 计（内地）。

### 3.3 云电脑 / 云桌面为什么不合适

阿里云无影、腾讯云电脑这类产品按「核时」或「包月时长」卖。个人版 40 核时 = 14.9 元/月听着便宜，但 **2 核跑满 7×24 需要约 1,460 核时/月**，等于买 36 份套餐；企业版 4C8G 虽然 199 元/年很香，但带「120 小时/月」的时长上限。**只适合白天用、晚上关机的场景，不适合常驻机器人。**

## 4. 推荐方案（按你的情况排序）

### 方案 A：大厂 Windows 轻量 —— 推荐给「要长期稳定、不想折腾」

- **腾讯云轻量 2C8G / 80G / 7M / 800 GB，Windows Server 2022，广州或上海**，约 100–130 元/月（走 ≥12 个月 85 折）。
- 理由：腾讯与 QQ 同属一家，到 QQ 服务器的链路最短，登录/收发体验最稳；轻量控制台简单，镜像里有 Windows Server 2022 数据中心版。
- 备选：阿里云轻量 2C4G+Windows（+20–30% 授权费），生态和文档更全。

### 方案 B：小厂 Windows VPS —— 推荐给「先验证、省钱优先」

- **雨云 2C4G（44 元/月起）**，国内机房优先，装 Windows Server 2022，先跑 1–2 周。
- 理由：这是目前**含 Windows 最便宜**的正经选择，且支持 7 天无理由退订——正好用来验证「这个 QQ 号在数据中心 IP 上会不会被踢」这个最大的不确定性。
- 风险：小厂 IP 段声誉差、带宽是共享的、宕机没有 SLA 赔付；QQ 风控对机房 IP 敏感，可能反复要求验证。

### 方案 C：Linux + 换网关 —— 长期最省，但现在不要动

- 用 NapCat（Docker/KVM 均可）替代 SnowLuma，Linux 2C2G 足够，年费可压到 200–400 元。
- 代价：`src/snowluma-conn.js`（214 行）要重写；`bridge.js`（11,713 行）里与 SnowLuma 专有语义绑定的功能（reserved2、转发消息、表情收藏、拍一拍、wake 配置、token 自愈）都要重新对齐。
- **建议**：等云端 Windows 方案跑稳、你对这套东西的依赖变重之后，再评估这个改造。

### 我的具体建议

> **先花 ~45 元在雨云买 1 个月 Windows 2C4G，把整套搬上去跑 3 天**，重点验证：QQ 能不能扫码登录、会不会被踢、RDP 断开后 QQNT 是否存活、4G 下 `Available MBytes` 还剩多少。
> **验证通过后**，买 **腾讯云轻量 2C4G + Windows Server 2022（广州），直接买 1 年或 3 年**，一次性把「续费翻倍」的坑绕过去。
> **只有在 4G 的余量被吃光（`Pages/sec` 长期 > 20）时，才原地升到 2C8G**——轻量支持升配，不用重装。
> 如果预算紧张，退而求其次选**京东云 2C4G/5M 三年 528 元**（务必先确认 Windows 加价后的实际总价）。

## 5. 迁移与运维要点（云端和本机的差异）

### 5.1 路径要全部重生成，别手工抄

本机的 `<你的用户目录>\.dsh\profiles\web\cordis.patch.yml` 里，三个 MCP 的 `command` 硬编码了 `'C:\Program Files\nodejs\node.exe'`，`args` 硬编码了 `<仓库路径>\src\*`（注意是下划线，和真实目录 `<仓库路径>` 不一致——这是笔记 §7 提到的「假失败」来源）。

云端：

1. 把仓库放到 **`C:\qq-bridge`**（别用带下划线的名字）；
2. `node scripts/setup-dsh.mjs` 重新生成 patch；
3. 生成完**手 grep 一遍**确认没有残留 `<仓库路径>`、`<你的用户名>` 之类的旧路径；
4. `config.json` 里 `snowluma.launcherPath` / `homeDir` 改成新机器的 SnowLuma 目录。

好消息：**所有端口仍然是 `127.0.0.1`（3000/3001/3080/3100/5099），bridge 与 DSH 的地址一个都不用改**，`dsh.allowRemote` 继续保持 `false`。

### 5.2 RDP 会话必须「断开」而不是「注销」

Windows 的坑：注销会让 QQNT 和所有 GUI 进程一起死掉。

- 用 `mstsc` 连上，操作完点右上角 ×（断开），**不要点「注销」/不要用 `logoff`**；
- 更稳的做法：配好**自动登录**（`netplwiz` 关掉「必须输入密码」），开机后由计划任务在控制台会话里拉起 `launcher.bat` 和 `start.bat`；
- 如果发现断开后 QQ 掉线，可以装一个 VNC（TightVNC/UltraVNC）保持「有活动会话」的假象，或设置 `tscon` 重定向回 console。

### 5.3 开机自启与守护

- 计划任务（触发器：登录时 / 系统启动后），分别拉起：
  - `C:\SnowLuma\...\launcher.bat`（SnowLuma，**EULA 禁止自动化部署，首次必须人工装、人工扫码**）
  - `node src\bridge.js`（qq-bridge，`start.bat` 已封装）
  - DSH Web（`dsh web` 或你当前用的启动方式）
- 建议配一个看门狗：每 5 分钟检查 `3000` 与 `3100` 是否在监听，不在就重启对应进程。

### 5.4 安全（云端比本机风险高，必须做）

| 项 | 怎么做 |
|---|---|
| 防火墙 | **只放 3389（RDP），并且只对你自己家的公网 IP 开放**；3000/3001/3080/3100/5099 **一律不要放行**，它们只绑 `127.0.0.1` |
| RDP 加固 | 改默认端口、强密码（≥16 位）、开账户锁定策略；条件允许用云厂商的「运维安全中心/VNC 控制台」代替公网 RDP |
| `state/` 令牌 | 本机已用 ACL 收紧；新机器上重做一次（只给当前用户 + SYSTEM），里面是明文 token |
| `config.json` | 不进 git（已被 `.gitignore` 忽略），云端单独备份一份到你的密码管理器 |
| 白名单 | `allowAllWhenEmpty` **必须保持 `false`**，`allow.private` / `allow.groups` 只留你自己的号 |

### 5.5 账单与续费

- 大厂首单/秒杀价**只限首次购买**，续费按原价；直接买 1–3 年把这段成本锁死。
- 流量超额 0.8 元/GB（内地），跑图片/语音多的月份注意看用量。
- 轻量**不支持降配**，只支持升配；买小了只能重装迁移。

## 7. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| **数据中心 IP 登录 QQ 被风控/踢下线** | 机器人反复掉线，最致命 | 先用按月小厂验证；内地地域优先；同一账号不要频繁换 IP 登录；掉线频繁就换厂商/换地域 |
| 首年特价续费翻倍 | 第二年成本翻 2–3 倍 | 直接买 1–3 年 |
| Windows 授权费 | 比 Linux 贵 20–30% | 接受它，或考虑 BYOL；不要买「仅 Linux」的活动机 |
| 4 GB 内存偏紧（尤其开了 RDP 或同时处理图片/语音） | 偶发卡顿、页面文件交换 | 按 §2.4 关掉 Defender 实时防护/系统服务；`Pages/sec` 长期 >20 就原地升 8G |
| RDP 会话中断导致 QQNT 死 | 服务静默离线 | 断开而非注销 + 自动登录 + 看门狗 |
| 小厂稳定性 / 无 SLA | 宕机、丢数据 | 只当验证机；`state/` 定期备份到对象存储或本机 |
| 单点故障（一台机器跑全部） | 机器挂了就全哑 | 可接受；把 `state/`、`config.json`、SnowLuma `config/` 三处做成每日备份 |
